# 渔获污染通报的批次归属与放行范围

沿岸检验站收到渔民语音转写、实验室通报和市场补报后，用本项目把中文记录处理成
**可复核的批次状态**：采样人员能判断样本对应哪个水域、哪次网次、回到谁手里补检；
检验人员能解释每份“未检出/检出”的适用范围；市场处置人员能据此执行局部暂缓、
扩大核查或解除限制。

> 全部海域、船名、人员、机构、化验单与检测编号均为**合成演练资料**，
> 不对应真实人员、机构、地点或业务决定。

## 三条不可破坏的纪律

1. **不能错并批次。**
   - 水域只承认 `data/case.json` 中 `waters` 表的规范名与显式别名：
     “石湾口”按别名表 → A-1 石湾外口；“石湾礁”是另一个水域 A-3；
     泛称“石湾”“石湾一带”不做子串猜测，登记为 `AREA_UNRESOLVED` 待人工核实。
   - “海星”有 B-1、B-2 两艘重名船。优先用背景登记的 `boats[].appears_in`
     编号关联；没有登记时，靠原文“另一船海星”+ 当前作业船做相对判断；
     仍不能确定就标记 `ambiguous_same_name`，绝不合并。
   - “昨天那片网也有”这类话只是**线索**（`Lead`），存在“同潮相邻网次”与
     “邻船另一次作业”两种解释，核实前不并批、不扩判；核实后也只是建立
     风险关联，网次批次仍各自独立。

2. **“未检出”不能覆盖整船货。**
   每份检测生成适用范围陈述，结论只对实际送检的**批次/箱位 + 组织部位 +
   指标 + 方法**有效。FC-2 是 FC-1 箱 4 的**鳃组织**、方法未载明的阴性结果，
   按 `policy` 不构成整箱放行依据，更不能覆盖箱 5–9 或 B-2 的货。
   只有“肌肉/可食部 + 认可方法 SYN-LCMS-01 + 未检出”才支持对应箱解除。

3. **已发出的暂缓通知不能当作没发生。**
   `Notice` 与台账事件全部冻结、只追加。追补的阴性结果只会**追加**
   `lift` 通知并引用原暂缓通知；`NOTICE-001` 始终留在台账中，其派生状态
   从“仍在执行”变为“部分箱已解除，余量仍执行”。

## 运行

Python 3.11+，无第三方运行依赖。

```sh
# 处理 data/case.json，生成 out/state.json、out/report.md、out/ledger.jsonl
python3 -m fishery_station build --case data/case.json --out out

# 只运行业务不变量自检（退出码非 0 表示失败）
python3 -m fishery_station check --case data/case.json

# 单元测试（含原始资料稳定性测试）
python3 -m unittest discover -s tests -v
```

也可 `pip install -e .` 后使用 `fishery-station build ...`。

## 合成演练案例的最终结论

| 批次 | 来源 | 船 | 水域/网次 | 箱号 | 当前处置 |
|---|---|---|---|---|---|
| LOT-001 | FC-1 | B-1 海星（老陈船） | A-1 石湾外口 / 11-25 夜 第3网 | 4-9 | **局部暂缓**：箱 7 检出支持暂缓、箱 9 同批扩查且缺样；箱 4/5/6/8 已凭合格补检追加解除 |
| LOT-002 | FC-3 | B-2 另一艘海星 | A-2 南礁 / 11-26 晨 第2网 | 1-3 | **可继续流通**，与 B-1 不并批；列入常规补检，归还 B-2 林秀 |
| LOT-003 | FC-8 | B-1 海星（老陈船） | A-1 石湾外口 / 11-25 傍晚 第2网 | 1-3 | **扩大核查**：FC-7 线索 + FC-8 强匹配，NOTICE-004 暂控；FC-13 已确认线索指向本批，但仍缺样 |
| LOT-004 | FC-10 | B-3 闽沙渔运06 | A-3 石湾礁 / 11-25 下午 第1网 | 11-12 | **可继续流通**；FC-13 排除其与线索有关；常规补检归还 B-3 |

- **哪个检测支持哪个决定**：见 `out/report.md` 第二、四节，或 `state.json`
  的 `tests[].scope_statement` 与 `evidence_matrix`。
- **哪些批次仍缺样**：最终缺 LOT-001 箱 9、LOT-002 箱 1-3、LOT-003 箱 1-3、
  LOT-004 箱 11-12（箱 4 已由 FC-12 补齐闭环）。
- **补检回到谁手里**：`state.json` 的 `actions[]` 中每个开放 `sampling`
  任务都带 `return_to`（稳定船 ID、负责人、合成电话、泊位）；
  FC-11 的“石湾一带”泛称另生成归还 B-3 周老大的澄清任务。

## 代码结构

```
data/case.json              # 来源记录（原文/编号/类型）+ 水域表 + 船只背景 + 演练规则
fishery_station/
  models.py                 # 冻结领域对象、状态码与中文标签
  parsing.py                # 中文规则解析：箱号、结论、组织窗口、方法、相对时间、水域表面形式
  resolution.py             # 水域别名解析；重名船/“另一船”/别称消解
  engine.py                 # 逐记录受理：建批、适用范围、只追加通知台账、线索、待办、状态折叠
  checks.py                 # 可复核不变量（引用完整性、解除不越界、问题必登记等）
  present.py                # state.json 视图与中文 Markdown 报告
  cli.py                    # build / check 子命令
tests/                      # 解析、实体消解、台账不可变、端到端结论、CLI 测试
out/                        # 最近一次生成的复核产物
```

## 接入新记录

把新的来源记录按 `{id, text, kind}` 追加进 `data/case.json` 的 `records`
（保持受理顺序；追补化验单放在后面即可）。若出现新的规范水域/别名或新船只，
同步补登 `waters`、`boats`。解析不了的表述会进入 `issues`/`actions`，
而不是被猜测合并。
